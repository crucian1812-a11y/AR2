# Собственные ассеты через Blender

Blender подключён **как модуль Python** (`bpy`), а не как приложение с окном.
Дисплей не нужен, всё работает в контейнере и в CI.

## Установка

```bash
python3 -m pip install --break-system-packages bpy
```

Скачивается около 300 МБ, ставится один раз. Версия — Blender 5.0.

## Генерация

```bash
python3 tools/blender/build_assets.py            # все ассеты
python3 tools/blender/build_assets.py turtle     # только один
```

Готовые FBX кладутся в `unity/Assets/Resources/Models/custom/` и
коммитятся в репозиторий вместе с кодом. Настройки импорта им задаёт
`ModelImportSettings`: скелета нет, материалы берутся из самого файла.

## Собственный герой

`build_hero.py` собирает «Железного человечка» — играбельного персонажа,
а не реквизит. Разница принципиальная: реквизит это статичный меш, а
герою нужен скелет и клипы, которые игра ищет по именам.

```bash
python3 tools/blender/build_hero.py     # unity/Assets/Resources/Models/monsters/IronSteve.fbx
python3 tools/blender/preview_hero.py   # лист поз из каждого клипа
```

Устройство:

- Пропорции Стива из Minecraft в «пикселях» (1 px = 1/16 блока): ноги
  0–12, корпус 12–24, голова 24–32, руки 12–24 по бокам. Считать надо
  именно от земли — с центром корпуса на 12 вместо 18 он налезает на
  ноги, а голова с руками повисают над дырой.
- Скелет из семи костей: Hips, Spine, Head, Arm.L/R, Leg.L/R. Каждая
  деталь целиком принадлежит одной кости (весовая группа с весом 1), и
  привязка идёт через `ARMATURE_NAME`, а не автовесами: кубам нельзя
  «плыть».
- Семь клипов: Idle, Walk, Run, Jump, Bite_InPlace, HitRecieve, Death.
  Имена не наши — так их ищет `CharacterModel`.
- `bake_space_transform=False`, в отличие от статичного реквизита: для
  оснащённых моделей запекание системы координат ломает позы.

Проверить, что клипы дошли до FBX, можно не открывая Unity:

```bash
strings unity/Assets/Resources/Models/monsters/IronSteve.fbx | grep '|Idle$'
```

Свечение реактора и глаз в модель не запекается — FBX переносит эмиссию
ненадёжно. Ореол и точечный свет добавляет `BearPlayer.ApplyHeroFx`.

## Превью

Играть в контейнере нельзя, а посмотреть на модель до того, как она
попадёт в мир, надо:

```bash
python3 tools/blender/preview.py cottage windmill well   # отдельные ассеты
python3 tools/blender/preview.py village                 # деревня в сборе
```

Картинки ложатся в `tools/blender/preview/`, отдельные ассеты ещё и
склеиваются в общий лист. Рендер идёт на Cycles/CPU: EEVEE требует
GPU-контекст, которого в контейнере нет.

Проверка окупилась сразу: первый же рендер показал, что скаты крыш
разлетаются (неверная ось поворота), а планки полотна у крыльев мельницы
лежат вдоль лонжерона вместо поперёк. По названиям функций этого не
видно никак.

## Грабли

`join()` наследует трансформ **первой** детали, а у неё сдвиг, поворот и
масштаб почти всегда неединичные — остальные меши пересчитываются в её
систему координат. Пока объект не трогают, это незаметно, но стоит
задать ему свой трансформ, и модель разъезжается. Собранная коллекция:

| Что унаследовалось | Как выглядело |
|---|---|
| масштаб | дом вытягивался в башню |
| поворот | крест крыльев уходил в другую плоскость (втулка повёрнута на 90°) |
| сдвиг | башня мельницы проваливалась на 4.6 м под землю (первый ярус построен на z=4) |

Поэтому `join()` запекает всё три в вершины: `transform_apply(location,
rotation, scale)`. У объекта остаётся единичный трансформ, а меш лежит
ровно там, где его построили — основанием в нуле.

Проверять такое глазами бесполезно: измеряйте габариты.

```python
zs = [(o.matrix_world @ mathutils.Vector(c)).z for c in o.bound_box]
print(o.name, min(zs), max(zs))
```

Именно так нашлось, что башня стоит от −4.58 до 5.92 вместо 0…10.5 —
на рендере это читалось просто как «крылья висят высоковато».

## Привязка по высоте

`Gfx.CustomProp` ставит модель **низом** в заданную точку: дерево должно
стоять на земле. Для вращающейся детали это неверно — у неё есть флаг
`anchorCenter`. Крылья мельницы симметричны относительно втулки, и от
сдвига «низом в ноль» их центр уезжал на пол-размаха вверх: круг махов
получался вдвое больше и нырял под землю.

## Как добавить новый

1. Написать функцию в `build_assets.py` по образцу существующих:
   собрать примитивы, назначить материалы, вызвать `join` и `export`.
2. Добавить её в словарь `ASSETS`.
3. Запустить генерацию, закоммитить получившийся FBX.
4. В мире вызвать `Gfx.CustomProp(...)` — модель нормируется по высоте
   и получает коллайдер по мешу, так что по ней можно ходить.

## Почему не blender-mcp

Расширение `blender-mcp` соединяется по сокету с **запущенным окном
Blender** на машине пользователя. Здесь код выполняется в удалённом
контейнере без дисплея, и до Blender на твоём компьютере он дотянуться
не может. Скрипты через `bpy` дают тот же результат — модели в игре —
и вдобавок воспроизводимы: ассет описан кодом и пересобирается одной
командой.
