# Собственные ассеты через Blender

Blender подключён **как модуль Python** (`bpy`), а не как приложение с окном.
Дисплей не нужен, всё работает в контейнере и в CI.

## Установка

```bash
python3 -m pip install --break-system-packages bpy
```

Скачивается около 300 МБ, ставится один раз. Версия — Blender 5.0.

## Генерация

```bash
python3 tools/blender/build_assets.py            # все ассеты
python3 tools/blender/build_assets.py turtle     # только один
```

Готовые FBX кладутся в `unity/Assets/Resources/Models/custom/` и
коммитятся в репозиторий вместе с кодом. Настройки импорта им задаёт
`ModelImportSettings`: скелета нет, материалы берутся из самого файла.

## Что уже сделано

| Ассет | Где используется |
|---|---|
| `turtle_giant` | панцири, на которых стоит Черепахоград |
| `signpost` | указатели на развилках в деревне |
| `treasure_chest` | сундуки на площадках |

## Как добавить новый

1. Написать функцию в `build_assets.py` по образцу существующих:
   собрать примитивы, назначить материалы, вызвать `join` и `export`.
2. Добавить её в словарь `ASSETS`.
3. Запустить генерацию, закоммитить получившийся FBX.
4. В мире вызвать `Gfx.CustomProp(...)` — модель нормируется по высоте
   и получает коллайдер по мешу, так что по ней можно ходить.

## Почему не blender-mcp

Расширение `blender-mcp` соединяется по сокету с **запущенным окном
Blender** на машине пользователя. Здесь код выполняется в удалённом
контейнере без дисплея, и до Blender на твоём компьютере он дотянуться
не может. Скрипты через `bpy` дают тот же результат — модели в игре —
и вдобавок воспроизводимы: ассет описан кодом и пересобирается одной
командой.
