# Анимации через Blender

Blender подключён **как модуль Python** (`bpy`), а не как приложение с
окном: дисплей не нужен, всё работает в контейнере и в CI.

```bash
python3 -m pip install --break-system-packages bpy   # ~300 МБ, один раз
```

## Зачем своя болванка, если модели берутся у Quaternius

Анимации делаются здесь, а модели лежат у пользователя. Связывает их
**Humanoid**: Unity отображает кости любого гуманоидного скелета на свой
эталонный и переносит клип с одной модели на другую. Клип, снятый на
болванке из `rig.py`, проиграется на бойце из пака.

Плата — расхождение пропорций: точка, где рука касалась соперника, при
переносе уезжает на несколько сантиметров. Лечится это IK поверх клипа, а
не более точной болванкой (§4 в `docs/bjj/PLAN.md`).

## Файлы

| Файл | Что делает |
|---|---|
| `rig.py` | скелет из 21 кости в T-позе + кубическая болванка |
| `poses.py` | парные позы для каждой позиции графа |
| `build_anims.py` | клипы и экспорт `unity/Assets/Resources/Models/fighters/Fighter.fbx` |
| `preview.py` | рендер поз в картинки |

```bash
python3 tools/blender/build_anims.py        # собрать FBX
python3 tools/blender/preview.py Mount      # посмотреть одну позицию
python3 tools/blender/preview.py            # все
```

## Главное решение: парные позы ставятся в одной сцене

Позиция партера — это не «поза верхнего» плюс «поза нижнего», а их
взаимное зацепление: колено давит в бедро, рука подмышкой, голова с одной
стороны. Роли, сделанные по отдельности, гарантированно разъедутся.

Отсюда следует и то, как клипы работают в Unity: **оба бойца стоят в одной
точке мира, а всё взаимное расположение лежит в самой анимации**. Так
делают все парные захваты. Иначе смещение применяется дважды — раз из
`Staging.cs`, раз из клипа, — и бойцы расходятся тем сильнее, чем длиннее
серия переходов.

## Имена клипов

`<роль>_<что>`: `Top_Mount`, `Bottom_Pass_Closed`. Позиция в игре — это
пара клипов, по одному на бойца.

- суффикс совпадает с позицией (`Mount`, `ClosedGuard`) — удержание,
  зацикливается;
- иначе это переход, играется один раз.

Так их и различает `ModelImportSettings.IsHold`. Blender называет тейки
`Armature|Top_Mount`, префикс срезается на импорте.

## Позы задаются в локальных осях кости

```
X — сгиб (колено, локоть), основная ось
Y — скрутка вдоль кости
Z — отведение в сторону
```

Локальная ось Y кости всегда направлена от головы к хвосту, поэтому запись
не зависит от того, куда кость смотрит в позе покоя.

Ключ `root` — положение **таза в мире**, а не смещение объекта. Это не
придирка к формулировке: у лежащего бойца поворот на −88° уводит начало
координат далеко в сторону, и первая версия именно так посадила верхнего
бойца в воздух на полтора метра. Теперь `apply` считает положение объекта
сам: `location = таз − R·(таз в позе покоя)`.

## Проверять позы глазами обязательно

В коде поза — это список углов; по нему не видно ни руки, прошедшей сквозь
грудь соперника, ни бойца, висящего над татами. `preview.py` рендерит три
ракурса и **меряет габариты**: провал под татами печатается отдельной
строкой, потому что под удачным углом его не разглядеть.

Рендер идёт на Cycles/CPU — EEVEE требует GPU-контекст, которого в
контейнере нет. Три ракурса одной позиции считаются около 20 секунд.

## FBX не лежит в репозитории

`Fighter.fbx` собирается **в CI**, шагом «Собрать анимации в Blender», и в
git не коммитится (см. `unity/.gitignore`). Причины две, и вторая решающая:

1. Файл целиком описан кодом в этой папке. Держать рядом с кодом ещё и
   результат — значит добавлять к истории по несколько мегабайт при каждой
   правке позы, а правок поз будут десятки.
2. LFS-эндпоинт GitHub (`lfs.github.com`) закрыт сетевой политикой
   окружения, в котором идёт разработка. Положить туда файл отсюда нельзя
   в принципе, а обычным блобом — см. пункт 1.

Локально файл собирается той же командой и просто лежит вне git.

## Состояние

Механизм работает целиком: позы → клипы → FBX → LFS → Unity. Сами позы
пока черновые — читаются правильно (верхом видно как верхом), но требуют
доводки рук и точек контакта. Ближайшая работа — довести восемь позиций
по рендерам и добавить IK-привязку кистей в Unity.
