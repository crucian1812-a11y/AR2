# Ассеты: что тащить в GitHub, а что нет

## 0. Выбранный пак: Quaternius — Universal Base Characters

Источник: <https://quaternius.com/packs/universalbasecharacters.html>

**Что внутри:** 6 готовых персонажей (пропорции Superhero / Regular / Teen,
мужские и женские), ~13k треугольников на модель, **Humanoid-риг** с
поддержкой ретаргета в любом движке, 20 причёсок, форматы **FBX и glTF**.
Две сборки: `Standard.zip` (~122 МБ) и `Source.zip` (~599 МБ, с .blend).

**Лицензия: CC0.** Это отличная новость — можно свободно класть в публичный
репозиторий, коммерческое использование разрешено, атрибуция не требуется
(но по-человечески стоит указать автора в README).

**Два следствия, которые меняют план:**

1. **Анимаций в этом паке нет.** Они в отдельном паке
   [Universal Animation Library](https://quaternius.com/packs/universalanimationlibrary.html)
   (и UAL 2). Это библиотека **одиночных** анимаций — ходьба, бег, удары,
   базовые действия. **Парных клипов борьбы в партере там нет и быть не может.**
   См. §4 в `PLAN.md`: это и есть главный риск проекта, и пак его не закрывает.
2. **Стиль — стилизованный low-poly, не фотореализм.** 13k треугольников и
   плоские материалы — это принципиально другая эстетика, чем UFC. Задача
   «AAA-графика уровня UFC» на этом паке не решается никакими шейдерами.
   Развилка по арт-дирекшену описана в `PLAN.md`.

**Что заливать из пака:** только `Standard.zip`, и внутри него — только **FBX**
(движок выбран — Unity), не оба формата сразу. Плюс причёски. `Source.zip` с
.blend-файлами (599 МБ) в репозиторий не кладём вообще — он съест всю квоту LFS
и в сборке не нужен.

Файлы кладём «голыми», без `.meta`: настройки импорта задаются кодом через
`AssetPostprocessor`. Готовый и уже отлаженный `ModelImportSettings.cs` есть в
медвежьем проекте — он умеет ровно то, что нужно этому паку, включая срезание
Blender-префиксов `Armature|Idle` с имён клипов. Подробности в
[`FINDINGS.md`](FINDINGS.md) §3.

**Важно про риг:** у пака **Humanoid**-скелет, и в Unity его нужно импортировать
именно как Humanoid (`ModelImporterAnimationType.Human`) — тогда работает
ретаргет анимаций между моделями и, что важнее для нас, **IK**, на котором
будет держаться привязка рук к телу соперника в партере (см. §4 в `PLAN.md`).
Медвежий проект использует Legacy-риг — эту часть переиспользовать нельзя.

---

Короткое правило: **в репозиторий едет только то, что лежит внутри `Assets/`
и `ProjectSettings/`, вместе с `.meta`-файлами. Всё остальное — нет.**

Кладём в `unity/BJJGame/Assets/...`.

## 1. Что загружать — обязательно

| Что | Расширения | Зачем |
|---|---|---|
| **Модели бойцов** | `.fbx` | Скиннутые меши с ригом (Humanoid) |
| **Анимации** | `.fbx`, `.anim` | Главная ценность пака. Особенно **парные** клипы борьбы |
| **Текстуры** | `.png`, `.tga`, `.psd` | Albedo / Normal / Roughness / Metallic / AO / Mask |
| **Материалы** | `.mat` | |
| **Префабы** | `.prefab` | |
| **Аниматор-контроллеры** | `.controller` | |
| **Шейдеры** | `.shader`, `.shadergraph` | |
| **Звук** | `.wav`, `.ogg` | |
| **Сцены** | `.unity` | |
| **Настройки проекта** | вся папка `ProjectSettings/` | Без неё проект не собирается в CI |
| **Список пакетов** | `Packages/manifest.json`, `packages-lock.json` | |
| **`.meta`-файлы** | `.meta` | ⚠️ **Критично** — см. ниже |

### ⚠️ Про `.meta`-файлы

У каждого файла и каждой папки в `Assets/` есть парный `.meta` с уникальным GUID.
Именно по GUID Unity связывает префаб с моделью, материал с текстурой и так далее.
**Если загрузить `.fbx` без его `.meta` — все ссылки в сцене порвутся**, и материалы
слетят в розовый. `.meta` мелкие и текстовые, LFS для них не нужен.

Проверка перед заливкой: у любого файла в `Assets/` рядом должен лежать файл с тем
же именем и `.meta` на конце.

## 2. Что НЕ загружать — никогда

| Что | Почему |
|---|---|
| `Library/` | Кэш импорта. Гигабайты, пересоздаётся сама. Главный «убийца» репозиториев с Unity |
| `Temp/`, `Obj/`, `Logs/`, `Build/`, `UserSettings/` | Мусор сборки |
| `.csproj`, `.sln` | Генерируются IDE |
| Демо-сцены, промо-ролики, скриншоты из ассет-пака | Часто это половина веса пака и ноль пользы |
| Дубликаты URP / Post-Processing / Cinemachine внутри пака | Они приходят через Package Manager. Две копии = конфликт шейдеров |
| Папки `Editor/` с демо-туториалами | Ломают сборку в CI |
| `.keystore`, `.jks`, пароли | Только через GitHub Secrets |
| Сам `.unitypackage`, если он уже распакован | Двойной вес |

Всё это уже прописано в `unity/.gitignore`.

## 3. Лимиты GitHub — тут легко влететь

- Файл **> 100 МБ** git просто **не примет**. Отказ, а не предупреждение.
- Репозиторий целиком желательно держать **< 5 ГБ**.
- Поэтому в репозитории настроен **Git LFS** (`.gitattributes` в корне) — все
  `.fbx`, текстуры, звук и видео внутри `unity/` уходят в LFS автоматически.
- **Но у бесплатного LFS квота: 1 ГБ хранилища и 1 ГБ трафика в месяц.**
  Каждая сборка в CI выкачивает LFS-файлы — квота съедается быстро. Если ассеты
  весят больше пары сотен мегабайт, придётся либо докупать LFS-пакет
  (~$5/мес за 50 ГБ), либо держать тяжёлое сырьё вне репозитория.

Перед заливкой полезно посмотреть, что вообще весит:

```bash
# 10 самых тяжёлых файлов в паке
du -ah . | sort -rh | head -20

# всё, что больше 100 МБ — это стоп-лист
find . -type f -size +100M
```

## 4. Лицензии — вопрос закрыт

Пак Quaternius распространяется под **CC0**, поэтому проблемы нет: репозиторий
`crucian1812-a11y/AR2` публичный, и это нормально. Приватным делать не нужно.

Единственное, за чем стоит следить: если позже добавятся ассеты с Unity Asset
Store или другие платные — почти все они запрещают публикацию исходников в
открытый доступ. Тогда репозиторий придётся делать приватным, и **до** первой
заливки: вычистить файл из истории git гораздо труднее, чем не коммитить его.

## 5. Как именно заливать

Веб-интерфейс GitHub («перетащить в браузер») **не подходит**: он не умеет LFS,
режет большие файлы и ломает структуру папок с `.meta`. Нужен git локально:

```bash
git clone https://github.com/crucian1812-a11y/AR2.git
cd AR2
git checkout claude/bjj-game-unity-09ry6v

git lfs install          # один раз на машине

# кладём распакованный ассет-пак в unity/BJJGame/Assets/
git add unity/
git status               # ← проверить, что не заехали Library/ и Temp/
git commit -m "assets: import <название пака>"
git push -u origin claude/bjj-game-unity-09ry6v
```

Если `git status` показывает тысячи файлов из `Library/` — значит `.gitignore`
не подхватился, останови и напиши мне.

## 6. Что мне нужно от тебя по ассетам

**Дерево файлов распакованного пака** — сами файлы пока не нужны:

```bash
# из папки с распакованным паком
find . -type f | sort
du -sh .
```

Хочу увидеть точные имена файлов и то, какие форматы ты скачал (Standard или
Source, FBX или glTF) — чтобы сказать, какие конкретно файлы копировать, а не
описывать абстрактно.

И отдельно: **скачивал ли ты Universal Animation Library**? Список её клипов
определит, что вообще можно анимировать в стойке. Партер всё равно придётся
решать отдельно — см. §4 в `PLAN.md`.
